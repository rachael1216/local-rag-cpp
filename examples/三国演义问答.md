# 示例：向《三国演义》提问

这份示例用仓库自带的 `novel.txt` 演示从建库到提问的完整过程，并给出一批可以直接复制的问题。

先说明一点：`novel.txt` 只收录了《三国演义》的**前十回**（从"宴桃园豪杰三结义"到"勤王室马腾举义"），所以它只回答得了这十回以内的问题。官渡、赤壁、诸葛亮出山这些后面的情节，书库里没有。这一点在下面的"边界测试"里也会用到。

## 准备

按[操作指南](../docs/GUIDE.md)完成编译和模型下载后，在仓库根目录运行：

```bash
./build/main_rag --ingest novel.txt novel.db
./build/main_rag --chat novel.db
```

## 一次完整的对话

下面是对话的大致形态。**回答部分只是示意**：模型每次的措辞都不一样，具体内容以你本地运行的结果为准，不要拿这里的文字当作标准答案去比对。

```text
Loading database from:novel.db

提问 >>> 桃园三结义是哪三个人？
Retrieved 3 relevant chunks.
刘备、关羽、张飞三人在桃园中结为兄弟，……

提问 >>> 曹操为什么要向董卓献刀？
Retrieved 3 relevant chunks.
……

提问 >>> 官渡之战谁赢了？
Retrieved 3 relevant chunks.
根据当前片段无法得出答案

提问 >>> exit
```

最后一个问题是故意设计的：官渡之战发生在这十回之后，库里没有相关内容。一个守规矩的回答应该是"无法得出答案"，而不是凭模型自己的印象作答。

## 可以直接试的问题

按问题类型分成三组，方便判断系统的表现。每个问题我都对照 `novel.txt` 确认过相关情节确实出现在前十回里。

### 事实型：答案集中在一两处原文里

这类问题最适合当前的系统，检索一般能命中。

- 桃园三结义是哪三个人？（第一回）
- 黄巾军的首领是谁？（第一回）
- 张飞为什么鞭打督邮？（第二回）
- 李肃是用什么东西打动吕布的？（第三回）
- 曹操向董卓献的是什么？结果怎么样？（第四回）
- 王允用的是什么计策？（第八回）

### 需要把几处内容串起来

这类问题取决于 `top_k` 能不能把相关片段都取回来，小模型的归纳也容易出错。先用默认设置试，不满意再把 `top_k` 调到 5。

- 董卓是怎么一步步掌握朝政的？
- 吕布先后跟过哪几个人，最后为什么杀了董卓？
- 孙坚在讨伐董卓的过程中做了哪些事？

### 边界测试：原文里没有的问题

用来检查系统会不会乱编。期望的回答是 `根据当前片段无法得出答案`，或者明确说片段里没有相关信息。

- 官渡之战谁赢了？（情节在第十回之后）
- 诸葛亮是怎么出山的？（同上）
- 罗贯中是哪一年出生的？（原文只有书名和作者名）

1.5B 的小模型偶尔会不听话，在这类问题上给出一个看似合理的答案。遇到这种情况，对照检索到的章节看一眼就能发现，这也是系统会带出章节标签的原因。

## 观察检索效果的小办法

想知道一个问题为什么答得不好，可以分两步看：

1. 先把 `top_k` 调大（比如 5）再 `/reload`，看回答有没有变好。变好了说明之前是检索漏掉了片段。
2. 把问法换成原文里更可能出现的字眼。检索靠语义相似度，但问题里带上原文用词（"鞭打督邮"而不是"张飞打了一个官员"）命中率会高不少。

## 换成别的文本

把 `novel.txt` 换成你自己的 UTF-8 文本即可，步骤见[操作指南第 8 节](../docs/GUIDE.md#8-换成自己的文本)。
